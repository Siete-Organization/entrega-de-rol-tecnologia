1. Cómo trabajamos

Lo mínimo para orientarte antes de abrir cualquier repo.

Dos empresas, un equipo

Siete es la agencia de prospección B2B: sus apps internas son AISDR, Outply, Response Manager, Marketing AI Engine y Siete Academy. Leaf es la consultora de certificaciones de sostenibilidad (EDGE, LEED, WELL…): sus herramientas son AI Consultor, AI Auditor y los flujos de n8n.

Dónde está cada cosa

  • Tareas y prioridades: PM Tech.
  • Código: Siete-Organization y Leaf-Global en GitHub.
  • Despliegue: Coolify (Siete y Leaf).
  • Login de las apps: Firebase Authentication, un proyecto por app.

Cómo sale algo a producción

En casi todos los repos, un push a main despliega automáticamente en Coolify. Por eso los cambios van por rama y PR, con el CI en verde. Cada ficha dice cómo se despliega ese proyecto en particular.

Stack

Despliegue
siete-soporte corre como Docker Compose en Coolify (proyecto «AI Support Sync»: servicio soporte + postgres:16-alpine). entrypoint.sh corre alembic upgrade head antes de arrancar y, si la migración falla, el contenedor no levanta. En PM Tech, un merge a main despliega por el webhook de Coolify («PM 21 Manager → Platform»). Cada app se despliega por su lado.
En local
uv venv && uv pip install -r requirements-dev.txt, ver .env.example, python -m alembic upgrade head y python -m uvicorn app.main:app --port 8100. Tests: python -m pytest (levanta un Postgres 16 embebido) y npx playwright test para el widget. En desarrollo, /dev/demo/aisdr.html (y unibox, outply) muestra el widget sobre maquetas de cada app.
Cosas a saber
  • widget.vN.js está congelado con SRI: cambiarlo exige publicar widget.v(N+1).js y abrir un PR en cada app.
  • .gitattributes fuerza LF. Con CRLF, entrypoint.sh no arranca y el hash del widget cambia. Hay que tener cuidado al editar en Windows.
  • Si la app no está conectada o siete-soporte no responde, el botón no aparece y la app no muestra ningún error. Un «no veo el chat» casi siempre es de configuración o de DNS, no de código.
  • Al conectar una app, el identificador tiene que ser el que usa su widget: marketing-ai, response-manager, aisdr u outply.
  • Para volver atrás el PM con la migración 0016, primero se corre alembic downgrade -1 en el contenedor api y después se hace el rollback de la imagen. En el orden inverso, el contenedor no arranca.
  • Las secciones viejas del HANDOFF describen un esquema de conexión que ya no se usa: lo vigente es «ESTADO AL 14/10» y «ESTADO AL 06/10». El módulo app/modules/feedback/ está vacío: la encuesta de satisfacción nunca se implementó.

Para arrancar

Stack
Backend en FastAPI con SQLAlchemy 2 async y Alembic (Python 3.11), con Celery y Redis. Frontend en React 19, Vite 7, TanStack Query y shadcn/ui. Usa una base Postgres propia y la base de Siete (core.contacts_master, companies_master). Auth con Firebase. Para la IA usa OpenAI, con Claude Haiku de respaldo, y además Apollo y ZeroBounce.
Despliegue
Coolify, proyecto «AI SDR». El repo trae dos formas de desplegar: el Dockerfile raíz (todo en un contenedor con supervisord) y docker-compose.yaml (api, redis, workers por cola y beat por separado). deploy/README.md explica cómo pasar de una a otra. Las migraciones corren al arrancar, y si fallan, el contenedor arranca igual. El CI corre en cada PR a main.
En local
Seguir la sección «Setup local» de README.md: pip install -e . en backend y npm install en frontend. Luego levantar Redis, uvicorn app.main:app --port 8000, npm run dev y un worker de Celery. Variables: ver .env.example. Las pruebas arman el schema desde los modelos, como el CI, y necesitan Postgres 16 con unaccent y pg_trgm.
Cosas a saber
  • Antes de elegir el ID de una migración, corre alembic heads. Los ID siguen de la a a la z y luego aa, ab…, y uno repetido deja dos cabezas y rompe el deploy.
  • La cadena de Alembic no construye la base desde cero (se corta en 88f31c6e8470). Además, cuatro tablas las crea backend/scripts/ensure_apollo_keys.py en cada arranque: no les agregues migraciones. Por eso alembic check solo sirve como lo usa el CI.
  • Hay dos caminos hacia Outply: el push del pipeline (workers/reply_push.py) y el de la carga manual (manual_upload._step_reply_push). Un filtro que se agrega a uno no cubre el otro.
  • AISDR y Outply comparten core.contacts_master: Outply anota ahí los rebotes (#119 y #127 de Outply), y AISDR descarta en la carga lo que tiene times_bounced > 0.
  • Los errores van a la tabla error_events y a Slack (#aisdr-alerts).
  • README.md y docs/documentation.md describen la versión que empujaba a Reply.io, así que parte está desactualizada.

6. Convenciones y glosario

Convenciones del equipo

  • Push a main = deploy en casi todos los repos. En Siete Academy, en cambio, un merge desde la UI de GitHub no dispara el deploy (docs/DEPLOY_COOLIFY.md). Confírmalo en cada repo antes de mergear.
  • No encender flags visibles para usuarios de lunes a viernes de 09:00 a 12:00, hora de Lima.
  • Commits y PRs en español, en el estilo tipo(área): qué cambia (Marketing AI está en inglés).
  • Varios repos tienen un CLAUDE.md con sus reglas, y usan openspec/ para especificar cambios antes de programarlos.
  • Las variables VITE_* y NEXT_PUBLIC_* se fijan en el build: si cambian, hay que reconstruir.
  • ENCRYPTION_KEY (Outply y Response Manager) tiene que mantenerse fija: si cambia, los buzones guardados quedan ilegibles.
  • En siete-soporte, fin de línea LF (.gitattributes): con CRLF no arranca el entrypoint.

Glosario

  • PM Tech: el tablero interno. Fases: No comenzado → En desarrollo → Feedback loop → Culminado.
  • Feedback loop: el proyecto ya está en uso y se ajusta con lo que dicen los usuarios.
  • CASA: Cloud Application Security Assessment, la evaluación que Google exige para apps con scopes restringidos de Gmail. La hace TAC Security.
  • WAT: el framework Workflows / Agents / Tools que usan varios repos (ver su CLAUDE.md).
  • Railway Pattern: resultados Ok/Err en lugar de excepciones (Outply).
  • Dosificador: la parte de Outply que reparte los envíos del día entre bandejas, dominios y campañas.
  • EDGE / LEED / WELL / SITES: certificaciones de sostenibilidad que gestiona Leaf. EEM y WEM son medidas de energía y agua de EDGE.
  • Pase: el token corto que emite siete-soporte para que el widget sepa qué usuario de qué app escribe.
